# GALACTYPE

指先から、宇宙へ。長文・単語・CPU対戦を楽しむ、宇宙テーマのタイピングゲーム。

文章選択・全文確認・入力・結果を、横スライドする4面のカルーセルで切り替えます。練習中は現在の一文と次の一文を表示し、先を読みながら自分のリズムで打てます。通常練習・タイプウェル・打鍵トレーナーは入力画面でSpaceを押すと3・2・1を表示し、3秒後から計測・入力を開始します。開始待ち・カウントダウン・一時停止を入力領域中央のオーバーレイに表示します。「Spaceでスタート」はクリックでも開始でき、「再開する」は大きなボタンで再開できます。開始用Spaceとカウント中の入力は打鍵・ミス・記録に含めません。Escape・フォーカス喪失・非表示・ページ／ステップ移動・やり直しでカウントを取り消し、再度Spaceで開始できます。一時停止からの再開にはカウントを挟みません。CPU対戦は従来どおりカウントダウンで同時に始まります。

## 起動

Node.js 24、pnpm 11.25.0 を利用します。

```sh
corepack enable
pnpm install
pnpm dev
```

ブラウザで http://localhost:5173 を開きます。ビルドは `pnpm build`、ビルド結果の確認は `pnpm preview`。静的ホスティングには `dist/` を配置できます（ルートパス配信を想定）。

## ソースコードの構成

エントリーポイントは `src/main.tsx` です。機能の画面と、Reactに依存しない処理を分けています。

| 場所                              | 責務                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------- |
| `src/app/`                        | Appの組み立て、アプリ全体のスタイル、背景                                    |
| `src/features/practice/`          | 通常練習の選択・プレビュー・入力・統計画面、セッション制御・計時・シード保存 |
| `src/features/battle/`            | CPU・ゴースト対戦の画面と対戦用ガイド                                        |
| `src/features/history/`           | 記録一覧・詳細分析・リプレイ表示、履歴購読・書出し・削除                     |
| `src/features/settings/`          | 設定の保存・設定ダイアログ                                                   |
| `src/features/library/`           | 問題集選択とカテゴリ                                                         |
| `src/features/results/`           | 各モード共通の結果表示                                                       |
| `src/domain/typing/`              | 入力判定・配列・読み位置・採点・単語境界                                     |
| `src/domain/content/`             | 問題集定義、本文・読み、出題順・シード                                       |
| `src/domain/battle/`              | CPUとゴーストの対戦ルール・進行                                              |
| `src/domain/records/`             | 記録の型、集計、トレース、リプレイ計算                                       |
| `src/infrastructure/persistence/` | localStorage・IndexedDBへの保存                                              |
| `src/shared/typing/`              | 練習・対戦・リプレイで共有する本文・読み・キーボード表示                     |
| `src/shared/ui/`                  | 機能を知らない汎用UI部品                                                     |
| `data/sources/original-long/`     | オリジナル長文21編のJSON原本と明示的な読み対応。                             |
| `src/data/generated/`             | 原本から生成されたアプリ用JSON                                               |

依存は `app → features → shared / domain / infrastructure`、`infrastructure → domain` を基本とします。ドメインはReactや保存実装をimportしません（保存との結合テストを除く）。共有UIはfeaturesやappに依存しません。各機能から共通の結果・履歴表示を利用できますが、相互importを増やさず、画面間の接続はAppが担当します。

新規ファイルはまず担当機能へ置き、複数機能で共有する純粋処理をdomain、ブラウザの保存APIを扱う処理をinfrastructureに置きます。テストは対象モジュールに併置し、E2Eは `e2e/` にまとめます。生成物と原本の配置は次節の区分を守ります。

### Appと各機能の境界

`app/App.tsx` は画面の接続を担当し、`AppShell` が背景・ナビゲーション・ヘッダーを描画します。練習・履歴のhookはAppの寿命で保持し、別画面へ移動しても練習の一時停止位置や履歴の選択を失いません。CPU・ゴースト画面は従来どおり画面を離れるとアンマウントします。

- `usePracticeSession`: 入力エンジン、状態遷移、採点、完了の一回性。UIには読み取り用の状態と開始・停止・リセット等の操作を返し、ゲーム内部のsetterを公開しません。
- `usePracticeClock` / `usePracticeFocus` / `usePracticeSeed`: 計時とカウントダウン、カルーセル移動後のフォーカス、保存済みシードと出題バージョン。それぞれが副作用の登録・解除を担当します。
- `domain/content/practiceDocument.ts` / `practicePreview.ts`: 出題の選択とプレビューの本文・読み対応。`domain/records/practiceResult.ts` は計測済みの入力から保存用記録を組み立てます。
- `useHistory`: 記録・ベスト・保存に失敗した記録の所有者。購読・保存・書出し・削除と詳細選択を一箇所で扱い、練習・対戦は完了記録を渡します。
- `useSettings` と各ダイアログ: 設定保存とダイアログUI。共通の `useModalFocus` がそのダイアログ内でフォーカスを循環し、閉じた際に元の操作へ戻します。ダイアログは画面遷移のtransformの影響を受けないAppShellの外枠に置きます。

## 問題データの配置と再生成

外部由来・提供された問題集は、開発用の原本・再生成用データとアプリが読み込むJSONを分けています。

| 場所                                            | 役割                                                                         |
| ----------------------------------------------- | ---------------------------------------------------------------------------- |
| `data/sources/rtc/`                             | RTC公式ZIPのローカル保存先（Git管理対象外）                                  |
| `data/sources/etyping/`                         | 提供XMLの原本                                                                |
| `data/sources/trainers/`                        | 保存HTMLからの抽出JSONと、さくさく15文の本文・読み・漢字の読み区切りJSON     |
| `data/sources/constitution/`                    | 公的本文のスナップショットと確認済みの読み注釈                               |
| `data/sources/typewell/`、`data/sources/space/` | 登録済みの単語・読みの再生成用スナップショット（取得HTML原本ではありません） |
| `src/data/generated/`                           | 上記から生成するアプリ用JSON8ファイル。直接編集しません。                    |

出典・原本の有無は [data/sources/README.md](data/sources/README.md) に記載しています。オリジナル6編と初期の宇宙64語は従来のTypeScript定義で管理します。

```sh
# Python 3の標準ライブラリのみ使用。ネット接続は不要
python3 scripts/rebuild-data.py
# 一時ディレクトリに再生成して照合。保存済みファイルは書き換えない
python3 scripts/rebuild-data.py --check
# RTCの全ZIP原本が必要な完全再生成・照合
python3 scripts/rebuild-data.py --require-rtc-sources
python3 scripts/rebuild-data.py --check --require-rtc-sources
# 再生成と照合コマンドのテスト（CIでも実施）
python3 -m unittest discover -s scripts -p 'test_*.py'
```

修正は `data/sources/` または `scripts/import-*.py` の読み対応に加え、一括再生成後にGit管理対象の入力と生成JSONをまとめてコミットします。RTC公式ZIPは再配布の許諾を確認できていないためコミットせず、`data/sources/rtc/*.zip` は `.gitignore` の対象です。過去のGit履歴は変更していません。通常の再生成ではWebから再取得しません。タイプウェルは `python3 scripts/import-typewell.py`、追加の恒星・星座は `python3 scripts/import-space-catalogue.py` でオンラインの再取得ができ、再生成用スナップショットとアプリ用JSONを両方更新します。内容・語順・抽出処理を変える場合は、履歴のシード・リプレイを保つため出題バージョンの更新も検討します。

`pnpm build` は保存済みの生成JSONをバンドルします。PythonやZIP/XML原本はアプリ実行時に不要で、`dist/` だけを静的HTTPサーバーに配置すればクライアント側で動作します。問題集を取得する外部通信やバックエンドはありません。CIでは同梱された再生成用データとの一致を検証します。RTCのZIPがそろわない場合は登録済みの `rtc.json` を維持し、ZIPとの照合をスキップした旨を表示します。RTCの生成データ自体の構造・読み対応・シード再現性は常にテストし、ローカルにZIPがある場合は原本のSHA-256・XMLとの一致も検証します。

## 練習

1. 「文章選択」画面に統合したライブラリのグリッドから、好みの一篇を選びます。ジャンルで絞り込み、タイトル・説明で検索できます。選択中のカードにチェックと枠を表示します。文学・旅・科学・日常・思索・音楽のオリジナル文章を各 3 段落、合計 6 編に加え、日本国憲法前文（4段落）の全文を収録しています。
2. 「全文を読む」で全段落を確認し、「この文章でスタート」で入力画面へスライドします。上部のステップでも移動できます。全文・文章選択へ戻ると一時停止します。画面は一度に1面だけ表示し、隠れた面はキーボード操作の対象から除外します。
3. 入力方式を選び、**IME を OFF / 直接入力**にします。入力領域をクリックし、Spaceキーを押します。3秒のカウントダウン後に計測と入力が始まります。句読点も入力します。
4. 入力に合わせてガイドが変わります。誤入力は進行せず、ミスとして計上。Backspace で戻す必要はありません。
5. Escape または一時停止で休止できます。入力欄からフォーカスが外れたとき、タブが非表示になったときも自動休止。再開ボタンから続きを打てます。休止時間は計測に含めません。
6. 全段落を完走すると記録し、専用の「結果」画面へ自動で切り替えます。「結果」ステップは完走後に選べます。途中の練習は保存しません。「やり直す」、文章・入力方式の変更で最初からになります。

本文は句点ごとに一文ずつ進み、次の一文を小さく控えめに表示します。本文の現在位置はシアンで強調し、入力済み部分は暗く表示します。漢字の連続部分は対応する読み全体を一つの単位として強調し、かなは一文字単位で進みます。かな入力の濁点・半濁点は入力し終わるまで同じ文字を強調します。ミスでは位置が進みません。独立した「現在の読み」欄は設けず、メイン文章の直下にひらがな、その下にローマ字、最後に次の文章を表示します。入力済みローマ字を残し、残りの候補と次の一打を表示します。入力ガイドは常に表示します。本文・ひらがな・ローマ字は折り返さず、それぞれ1行のまま入力位置へ滑らかに左送りし、画面幅変更にも追従します。かな入力ではローマ字を非表示にし、濁点の入力途中も「が」などを分断せず表示します。入力ガイドのON/OFF設定はなく、過去にOFFにしていても有効になります。かな入力はかなガイドを常時表示します。3D 背景も OFF にできます。オリジナル6編の本文と読みの対応は `src/domain/content/passageReadings.ts` の明示的なデータで管理し、全文との一致をテストしています。新しい文章を追加する場合は漢字の読み対応も追加してください。本文は漢字かな混じり、判定は手動で用意した読みを使います（助詞「は」は `ha`）。

キーボードガイドはEsc・F1〜F12の行を表示せず、数字行から始まる5行構成です。Escの一時停止操作は引き続き使えます。キーの共通ピッチ、行のずれ、Tab/Caps/Shift/Backspace/Spaceの幅、JISの縦長Enterを実物に近づけています。担当指ごとにネオンの色で区分し、F・Jにホーム位置の目印を表示します。次に押すキーだけが発光します（Shiftが必要な場合はShiftキーも発光）。選択したJIS／US／Dvorak／Colemak／Workman／大西／AZERTY／Norman／かな配列に連動し、必要なShiftは反対側の手を案内します。AZERTYのAltGr入力では右Altも案内します。かな入力の濁点・半濁点も別キーとして追従します。一時停止・完走中は発光を止めます。誤入力した物理キーは600ms赤く表示し、正解キーは色・枠・光のトランジションと再発光で強調します。通常練習・CPU対戦・ゴースト・苦手ワードで共通です。連続ミスは表示時間を更新し、一時停止・リセット・完走で消去します。OSの「動きを減らす」では動きやトランジションを止めて着色だけを残します。画面上のキーボードは表示ガイドで、クリック入力は行いません。

漢字の上には、対応データの読みをふりがなとして表示します。単語の色分けはデフォルトONです。右側の「単語の色分け」で本文・かな・ローマ字の配色を切り替えられ、保存済みのON/OFF設定を優先します。4面のカルーセルは同じ高さを維持し、次へ進むと左へ、前へ戻ると右へスライドします。全文確認では長い段落を画面幅に合わせて折り返し、縦にスクロールして確認できます。入力中の本文・かな・ローマ字はオリジナル長文も含めて折り返さず、1行表示を維持します。「入力済み単語を消す」をONにすると、打ち終えた単語を非表示にし、残りを左へ送ります。OFFでは従来どおり入力済み部分をグレーアウトします。どちらもこのブラウザに保存します。濁点・半濁点や漢字の読みの途中で単語を消すことはありません。入力中の送りはOSの「動きを減らす」に従い、スライドは環境設定の「画面切り替えのアニメーション」に従います。

各ページは上部のキャッチフレーズを省き、文章選択・対戦・記録の操作を直接表示します。

## 独自メニューと画面切り替え

入力方式・CPUプリセット・文章セット・打ち方・記録分析の比較対象と指標・リプレイ速度は、ブラウザ標準のプルダウンを使わず、共通の独自コンボボックスで表示します。クリック／タップに加え、矢印キー・Home/End・PageUp/PageDown・文字検索で候補を移動し、Enter/Spaceで確定できます。Tabは候補を確定して次のコントロールへ進み、Escape・外側クリックは変更せずに閉じます。無効な候補は選べません。DOMフォーカスは開いたコントロールに保ち、候補のフォーカスを`aria-activedescendant`で伝えます。メニューはスクロール枠の外に表示し、画面の上下・左右からはみ出さないよう配置します。[WAI-ARIA APGの選択専用コンボボックス](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/)を参考にしています。

ページの移動はフェード＋縦送り、カルーセルは進むと左へ、戻ると右へ、0.65秒かけてなめらかにスライドして切り替えます。回転と光のスイープは使いません。枠の高さは4面とも固定し、内容は枠内で縦にスクロールします。画面外の面は`inert`で入力対象から外します。環境設定の「画面切り替えのアニメーション」で「オン」（初期値）・「OSに合わせる」・「オフ」を選べます。「オン」ではOSの「動きを減らす」が有効でもページ・カルーセルの切り替えを動かし、「OSに合わせる」ではOS設定に従い、「オフ」では常に停止します。設定はブラウザに保存します。背景・打鍵・ミス・メニュー・結果の演出は引き続きOSの「動きを減らす」に従います。

## 追加の入力配列

入力方式は9配列に対応しています。通常練習・CPU対戦・ゴースト・苦手ワード・保存記録・リプレイで共通です。ローマ字の別綴りはそのまま受け付けます。OS側はQWERTYの英数入力・IME OFFにし、アプリが物理キー位置（KeyboardEvent.code）を選択配列に変換します。OS側でも同じ配列へ二重変換しないでください。

| 大西配列        | [大西配列公式](https://o24.works/layout/)の31キー（Minusを含む）を使用。`QWERTYUIOP → QLU,.FWRYP`、`ASDFGHJKL; → EIAO-KTNSH`、`ZXCVBNM,./ → ZXCV;GDMJB`、`Minus → /`。その他はUS記号。                                                                                                                           |
| AZERTY · French | [Microsoft French Legacy / KLID 0000040C](https://learn.microsoft.com/en-us/globalization/keyboards/kbdfr)を使用。フランス語ISO配置の縦長Enter・左Shift横のキーも表示。数字はShift、`@`や`[]`等はAltGr。AltGrの代わりにCtrl+Altでも入力可。デッドキーは単独の記号として扱います。AFNOR新標準配列ではありません。 |
| Norman          | [Norman公式の配列図](https://normanlayout.info/)を使用。`QWERTYUIOP → QWDFKJURL;`、`ASDFGHJKL; → ASETGYNIOH`、`ZXCVBNM → ZXCVBPM`。その他はUS記号。                                                                                                                                                              |

## 苦手ワード練習

左ナビの「苦手ワード練習」で、直近200件の通常練習・対戦等の保存ログ（反復練習自体は除外）からミスやタイムロスのある単語を選び、繰り返し練習できます。最大100候補を実ミス数・ロスの順に20語ずつページ表示し、最大20語・各1〜20回（初期値5回）を指定できます。ページを移動しても選択と繰り返し回数を保持します。完了画面の「今回の単語を候補から削除」で練習した語を候補から外せます。再読込後も削除状態を保持し、元の打鍵記録は消しません。新しい練習で同じ語にミスやロスが出た場合は再び候補になります。候補と削除マーカーはいずれも最大100件です。選んだ単語を1周ずつ、指定回数出題します。Space→3秒カウントで開始し、一時停止・やり直し・配列変更・完了時の統計とその場でのリプレイに対応します。苦手ワード練習の結果は履歴に保存せず、文章別分析と全記録にも含めません。候補選択・入力・完了画面を同じ枠付きワークスペースに表示します。

保存された本文と読みの対応に一致する単語境界だけを使い、漢字の読みを推測して分割しません。1文字の語・記号と、「から」「まで」「など」等の主な助詞は候補から外します。読み区切りが残っていない旧ログ・ログのない記録も除外します。ミスがなくても、正打鍵間隔の中央値に対して合計120ms以上の遅れがある語を候補に含めます。

結果は `weak` モードとして通常練習と分けて保存。同じ単語・順番・繰り返し回数なら同じセットとして比較し、セットが異なる記録は混ぜません。未完走の練習は保存しません。

## 終了画面

通常練習・e-typing・RTC文章セット・タイプウェル・60秒トレーナーを終えると、タイプウェルの記録確認を参考にした専用の結果面を表示します。pointと称号を大きく表示し、KPM・所要時間・正確率・正打鍵数・実ミス数、同じ文章セット／配列／モード／出題バージョンの過去最高と前回pointを確認できます。タイプウェルは基準400/280打と実打鍵数を区別します。ゴースト完走時も同じ形式の結果画面で勝敗とミスを確認できます。

結果には1秒ごとのKPMと5秒移動平均の速度グラフ、ミスの印を表示します。記録・詳細・結果の縦軸は上限を100の倍数に切り上げ、100刻みの主目盛りにラベル、50刻みの補助目盛りにラベルなしで統一しています。加えて、間違えた箇所（問題番号・文字・正解キー・実際の誤入力・回数・最初の時刻）、時間がかかった文章の上位5件を表示します。ミスは同じ問題・入力位置・正解キー・誤入力ごとに集計し、上位30箇所を表示します。ロスは正打鍵間隔の中央値を超えた待ち時間の目安です。グラフのKPMは正しい実打鍵数から算出するため、タイプウェルの基準打鍵KPMとは区別します。

速度統計は完全な1秒区間の正しい実打鍵KPMを使い、無入力の1秒は0とし、末尾の1秒未満をグラフ・統計から除外します。通常の最低・最高速度は参考値として残し、5秒平均の最低と通常の最低、5秒平均の最高と通常の最高をそれぞれ上下に配置します。グラフにホバー／タップするか、フォーカスして左右キー（Home／Endも使用可能）を押すと、秒区間のKPM・正打鍵・実ミス率・ミス数・入力した単語や文章・誤入力と正解キーをツールチップで確認できます。Escape／フォーカス解除で閉じます。**過去順位は5秒移動平均の最低・最高速度で比較**します。連続する完全な5秒分のKPMの単純平均を1秒ずつずらして計算し、短いウォームアップ窓は使いません。5秒未満のランは移動平均・順位の対象外です。

同じ文章セット・配列・モード・出題バージョン（CPU設定やゴーストの参照元も一致）の保存記録と今回を比較し、移動平均の最低速度も高いほど上位、同率は同順位です。ブラウザに保存されている全記録（残存TOP記録も含む）のうち、移動平均の要約または再計算できるログがある記録が対象です。従来の1秒統計だけが残る旧要約はログから再算出し、ログがなければ順位には混ぜません。ラン内の「5秒移動平均」と、記録間の「直近5回移動平均」は別の指標です。

区間平均・中央値・母分散（KPM²）・標準偏差・変動係数・90パーセンタイルと、打鍵間隔の平均・中央値・最大、最長連続ミスも表示します。新しい履歴は速度の要約も保存するため再読込後も比較でき、旧記録は残っている打鍵ログから算出します。休止時間は含めず、打鍵間隔の統計は0msを除外します。平均速度0の変動係数や、打鍵間隔の標本がない項目は—で表示します。タイプウェル本体の統計式の完全移植ではなく、上記の定義に基づくGALACTYPEの統計です。

「全打鍵・リプレイを確認」から、既存の秒ごとの推移・文字／文章のロス・全打鍵ログ・リプレイを開けます。結果の閲覧や再生では記録を追加しません。「もう一度」で入力面へ戻り、「文章を選び直す」で選択面へ戻ります。

CPU戦は各ラウンド終了時に専用の結果を表示し、そのラウンドの10点先取スコア・勝者・正確率95%による逆転の有無・point・ミス・速度推移・ログを確認してから「次のラウンド」へ進みます。ラウンドのログはそのラウンドを0秒とする時間軸で表示します。BO7全体を終えると勝利／敗北画面に切り替え、全体スコアと各ラウンドの勝敗一覧を表示し、「再戦する」へ進めます。カウントダウン・幕間・結果を見ている時間は計測に加えません。ラウンド単位の結果は対戦中に保持し、ローカル履歴への保存は従来どおり全対戦完了時の1件だけです。

## point・称号

point = floor(正打鍵KPM × 補正正確率²)、補正正確率 = 正打鍵数 / (正打鍵数 + 加重ミス数)。途中経過・完走結果・履歴にpointと称号を表示します。pointに上限はなく、1000pt以上は最高称号に固定します。

ptには連続誤打の加重ミス数を使います。1回目から順に重み1、0.75、0.5、0.35、0.25、以降も0.25を加算し、正しい打鍵で連続回数をリセットします。実際の誤打数とミス箇所数（連続誤打を1箇所に集約）は別に残し、既存の正確率表示・RTC判定はミス箇所数を使います。長い別表記の途中やかなの濁点でも、正しい打鍵が入れば次のミスを別に数えます。誤打で費やした時間は速度に反映されます。既存の履歴は当時のミス数でpointを算出し、「旧ミス方式」と表示します。

## CPU対戦

サイドバーの「CPU対戦」で設定し、開始します。対戦設定は開始前だけ表示し、対戦・幕間・一時停止・結果表示中は隠します。「対戦をリセット」で設定に戻れます。メインと右サイドバーは通常練習と同じ幅にそろえ、右側にpoint・KPM・正確率・時間・実ミス・ラウンド数・CPU設定の要約・表示オプションを表示します。小画面では通常練習と同じく下へ配置します。通常練習と同じ9配列・ふりがな・表示オプションが使えますが、**次の文章は表示しません**。「RTCオリジナル」の短文20問に加え、登録済みの全文章セットを選べます。e-typingの6セット、さくさくタイピング、憲法前文、タイプウェルの各辞書も使用でき、両者が同じ問題を同時に開始します。

- 一問を先に打ち切った側へ1点。10点先取で1ラウンド、4ラウンド先取（BO7）で勝利します。
- 先取した側が正確率95%未満、相手が95%以上なら相手がラウンドを獲得します。CPUは無誤打のため、プレイヤーが先に10点を取っても95%未満ならCPUのラウンドになります。正確率には同じ連続ミス集約を使います。同時完了は入力中の速度・正確率のトータルポイントで比較します。
- 各ラウンド冒頭に3秒のカウントダウン、各問題の終了後に650msの入力不能時間があります。連打の持ち越しによる意図しないミスを防ぎます。
- KPMはCPUの定常速度。反応時間は出題から**最初のキー**が入るまでの時間です。一定速度と、時定数700msで定常速度へ近づくイーズインを選べます。反応と加速を含む全体の実測KPMは設定値より低くなります。
- プリセットは称号と同じ21段階・35〜1035 KPMで、反応時間はカメ250ms〜チーター120msです。人間の反応をイメージしたゲーム内の調整用プリセットです。設定はこのブラウザに保存します。
- Escape、一時停止、フォーカス離脱、ブラウザの非表示で停止し、再開までCPUの時計も止まります。対戦中の設定変更はリセット後に行います。別のアプリ内画面へ移ると進行中のCPU対戦は終了します。完了した対戦だけを履歴へ1回保存します。

ルールの参照: [RTC2025公式の競技ルール](https://www.realforce.co.jp/events/202503_typing-championship/)、[Weather Typing公式FAQ（速度・正確性・トータルポイント）](https://denasu.com/software/wtfaq.html)。大会ワードはユーザー提供のRTC ZIP内XMLを使用しています（下記参照）。大会の画像素材は含めません。

| 方式       | 動作                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| QWERTY JIS | `KeyboardEvent.key` を使い、JIS の記号位置を OS に従って処理                            |
| QWERTY US  | `KeyboardEvent.code` で US 配列の物理キーを復元                                         |
| Dvorak     | 物理キーを標準US Dvorakに変換。OSはQWERTYのまま使用                                     |
| Colemak    | 物理キーを標準Colemak（Mod-DHではない）に変換。US記号位置、OSはQWERTY                   |
| Workman    | 物理キーを標準Workmanに変換。US記号位置、OSはQWERTY                                     |
| JIS かな   | 物理キーを JIS かなに変換。濁点・半濁点は別打鍵、小書き文字・句読点は Shift。IME は OFF |

Colemak／Workmanはアプリ内で物理キーの英数字・記号を変換します。文字判定には`KeyboardEvent.code`を使い、OSの文字出力に頼らず変換します。想定する操作環境はOSをQWERTYにした物理キーボードで、IMEをOFFにして使います。キーボードの表示文字・次キー・Shiftと指の色も配列に連動します。練習・CPU対戦・リプレイ・ゴースト・設定保存・記録比較で使用でき、タイプウェルは他のローマ字配列と同じ400基準打鍵です。Caps LockのBackspace化、AltGrの多言語入力やOSショートカットの変更は行いません。配列は[Colemak公式のUnix定義](https://colemak.com/Unix)と[Workman公式リポジトリのXKB定義](https://github.com/workman-layout/Workman/blob/master/xorg/workman)と照合しています。

### ローマ字判定

固定の正解文字列と比較せず、読み位置と未完の綴りを持つ候補集合で判定します。候補は入力ごとに絞り込み、別綴りを混ぜて入力できます。

- `し`: `shi / si / ci`、`ち`: `chi / ti`、`つ`: `tsu / tu`、`じ`: `ji / zi`
- `しゃ`: `sha / sya / shixya / silya` など、拗音の一括・分割入力
- 小書き文字の `x / l`、`っ` の `xtu / ltu / xtsu / ltsu`、子音重複 (`kka / ssya / tchi` など)
- `ん`: `nn / n' / xn`、後続が子音なら `n`。`んあ` は `nna`、`んな` は `nna / nnna`。末尾の `ん` 単独は `nn / n' / xn` を使用
- `ふぁ / うぃ / てぃ / でゅ / くぁ / ゔぁ` などの外来音と、小書き文字に分ける入力
- `、。ー「」！？` はローマ字方式では `,.-[]!?`

対応表は [src/domain/typing/engine.ts](src/domain/typing/engine.ts)、回帰例は [src/domain/typing/engine.test.ts](src/domain/typing/engine.test.ts) を参照してください。e-typing / Typewell の非公開判定仕様と完全一致することは保証していません。追加の綴りは判定表とテストの組で拡張できます。JIS 実機のメーカー固有キー・OS/ブラウザ差、および全 IME 固有拡張は未検証です。

ハードウェアキーボード向けです。スマートフォン幅では閲覧できますが、ソフトウェアキーボード入力は対象外です。

## 記録とプライバシー

- 集計履歴はlocalStorageの `yohaku.history.v1`（完了した全記録、苦手ワード練習を除く）、歴代TOP10は `galactype.bests.v1` に保存します。設定は `yohaku.settings.v1` / `yohaku.cpu.v1` / `galactype.cpu-prompts.v1`。全打鍵の詳細はIndexedDBの `galactype.telemetry.v1` に分けて保存します。外部サーバーへの記録送信はありません。
- 通常練習・CPU対戦のKPM = 正しく受け付けた実打鍵数 ÷ 実測分数。タイプウェルのスコア用KPMは固定の基準400/280打鍵で計算します。詳細分析の区間KPMは全モードで実打鍵数を使います。正確率 = 正打鍵 ÷（正打鍵 + ミス）× 100。
- 複数タブの履歴追加・削除を同期します。HTTPS / localhost の対応ブラウザでは Web Locks API で同時書き込みを排他制御。非対応環境でも保存直前に最新履歴へ統合しますが、同時書き込みの排他保証はありません。
- 文章・入力方式の組ごとに自己ベストを表示。かな入力とローマ字入力の KPM は直接比較しないでください。
- JSON v2書出しには保存済みの全履歴・歴代TOP10・保持している全打鍵ログを含めます。JSON 再取込機能はありません。
- 環境設定の「記録をすべて消去」、または記録画面の削除ボタンから、確認モーダルを開いて全履歴を削除できます。キャンセル／Escapeでは削除せず、確定すると履歴・TOP10・詳細ログをまとめて消去します。設定と文章セットは残します。設定から開いた確認を閉じると設定へ戻ります。削除処理中は二重実行を防ぎ、失敗した場合は確認画面を閉じずにエラーを表示して再試行できます。
- 保存が拒否された場合もメモリ内で練習できます。警告を表示し、履歴は JSON で退避可能。破損データは読み飛ばします。
- ブラウザのデータ削除・別端末・プライベートブラウズでは履歴を引き継げません。

## デザインと技術

React / TypeScript / Vite / Tailwind CSS v4 / Three.js / Lucide。濃紺・シアン・紫の宇宙テーマに、本文の影と現在位置のネオン発光を組み合わせています。正打鍵では短いリング・粒子が出ます。ミスタイプでは画面の縁に約 0.5 秒の赤いダメージ演出が出ます。全画面演出はクリックや打鍵を遮らず、連続ミスでも一つだけ表示し、一時停止・やり直し・完走で消去します。`prefers-reduced-motion` では正打鍵の演出を隠し、ミスは静的な細い枠で伝えます。

背景は恒星、異なる表面模様の 6 惑星、リング、星の粒子が奥行き方向へ流れる恒星系です。惑星の小さなテクスチャを端末内で生成し、画像の外部取得は行いません。Three.js は遅延ロードし、背景 OFF 時はロードしません。描画は最大 30 fps、ピクセル比 1.5・描画面積 160 万画素を上限とします。非表示タブではアニメーションを停止します。`prefers-reduced-motion` では静止し、リサイズ時のみ再描画します。WebGL が使えない場合やコンテキストを失った場合は CSS の惑星に切り替えます。背景 OFF・アンマウント時に描画ループ、イベント監視、ジオメトリ・マテリアル・テクスチャを解放します。

## タイプウェルの文章セット

専用のナビゲーションや独立したゲームモードは設けず、文章選択・ライブラリに「基本常用語」「カタカナ語」「漢字」「慣用句・ことわざ」「宇宙の名前」の5セットを追加しています。JIS/US/Dvorak/Colemak/Workman/大西/AZERTY/Normanでは国語R相当の400自然打鍵分、かな入力では国語K相当の280打鍵分です。単語は復元抽出で毎回ランダム、区切りの半角スペースも1打分に含めます。最後は単語・音節の途中でも終了します。

出題は入力を始める前に、文章セット・シード・配列からすべて確定します。単語をランダムに抽出してスペースでつなぎ、自然な短いローマ字表記を基準に400キーの参照列（かなは濁点別打鍵を含む280キー）を作り、末尾の単語・音節の途中にある終了位置まで固定します。入力中に次の単語を追加したり、表示範囲や末尾を作り直したりしません。最後の単語はふりがなを正しく見せるため全体を表示し、入力が必要なローマ字は固定の終了位置で切ります。

別の有効なローマ字表記は受け付けます。`sanka`と`sannka`は同じ「参加」までを打ち、余計な`n`で出題の末尾を移動しません。長い表記は実打鍵数だけ増え、終了までの基準打鍵数・KPM・ptを増やしません。通常の文章と同じくSpaceキーで3秒カウントダウンし、終了時から時計が動きます。休止中の時間は計測に含めません。

「シードを固定する」をONにし、任意の文字列を入力して「このシードを使う」を押すと再出題できます。OFFでは選び直し・やり直しのたびに新しい乱数シードを使います。再現IDはセットID / 出題バージョン / シード / 配列です。現行はv2で、出題範囲の固定と宇宙辞書の拡充を反映しています。新しい履歴にはバージョンも保存し、v1の履歴は旧シード処理・旧64語辞書を使って同じ基準キー列を再現します。乱数はFNV-1a + Mulberry32、プレイ中の外部通信はありません。

ルールの確認には[非公式ブラウザ版の出題・入力処理](https://github.com/fiore57/typewell-in-browser/blob/main/src/lib/typing.ts)と[タイプウェル国語R/Kの種目・打鍵数の記録](https://w.atwiki.jp/typer/pages/51.html)を参照しました。元ソフトそのものの完全移植ではありません。既存の1行表示・左送り・色分け・pt表示を共用します。最終単語は漢字と正しいふりがなを保つため全体を表示し、実際に必要なローマ字だけを終了位置で切ります。

## CPU対戦の文章セット・シード・得点表示

対戦設定の「文章セット」で選び、「対戦シードを固定する」をONにして任意のシードを入力すると、同じ文章セット・RTC出題v1・シードでBO7全体の問題順を再現できます。OFFでは開始・再戦ごとに新しいシードを発行します。文章セットと固定設定は保存し、完了した対戦の履歴からCPUのKPM・反応時間・打ち方・配列も含めて再設定できます。開始前に設定を確認し、「CPUと対戦する」で再戦します。

RTCは10点先取・4ラウンド先取を維持するため、ソロのe-typing系15問とは別に、最大7ラウンド×19問＝133問分をシードから用意します。問題プールをシャッフルし、使い切ったら再シャッフルして続けます。タイプウェルの辞書は1語を1問として出し、400/280打鍵の行をRTCの1問にはしません。入力中にシードや設定を変更できず、次の文章は表示しません。

現在のラウンド得点はYOU/CPUの大きな数字と10個の点灯ゲージ、先行状況で表示します。CPUの打鍵数・反応待ち／走行状態の補助テキストと単語進捗バーは表示せず、入力の進み具合は上下にそろえたローマ字の行で比較できます。得点時に短い発光アニメーションが入り、動きを減らす設定では停止します。キーボードは小指を青、薬指をピンク、中指をシアン、人差し指を星のようなアンバー、親指を青灰色にし、キー面と境界の色差を広げています。

## 打鍵の詳細と文章別の成績

完了した練習・60秒トレーナー・CPU対戦について、受け付けた全打鍵の経過時刻・直前からの間隔・正誤・入力とガイドの先頭キー・文章番号・読み位置・本文の文字グループを記録します。連続ミスは1回ずつ記録します。Ctrl等のショートカット、キーリピート、IME変換中の入力、停止中や問題間の入力不能時間のキーは記録しません。別の有効な綴りも正解として残します。記録対象はこのゲームの入力領域のみです。一時停止は計測に含めず、CPUのカウントダウン・問題間待機も除外します。

「練習の記録」→「詳細を見る」で次を確認できます。

- 1秒区間の実正打鍵KPM、実ミス率、累計ミス。グラフと表を120秒ずつ表示し、表示開始秒を動かして全区間を確認できます。最後の1秒未満の区間は実際の区間長でKPMを計算します。
- 正打鍵の正の打鍵間隔の中央値を基準とし、超えた時間が長いキー20件と文章ごとの待ち時間・KPM・ミス数。末尾の未入力時間は文章の待ち時間に加算します。「タイムロス」は基準を超えた時間の目安であり、ミスが原因だと断定する値ではありません。
- 全打鍵ログを100件ずつ表示。何秒目にどの文字・キーで止まったかを追えます。本文の漢字グループや辞書の1語は、その読み全体に対応します。

詳細分析のKPMは有効な別綴りも含む実打鍵数を使います。タイプウェルのスコア・履歴KPMは従来どおり固定の基準400/280打鍵を使うため、両者の値は区別します。旧記録に打鍵ログを補って生成することはなく、ログのない記録はその旨を表示し、集計値だけ比較します。

文章セット・配列・モード・出題バージョン（タイプウェルは基準打鍵数も）をそろえて、pointを主指標とした歴代TOP10、最新・前回point、前回との差、直近5回の単純移動平均と直近30回の推移を表示します。KPMも常に併記し、「記録の主指標」でグラフとランキングをKPMへ切り替えられます。5回未満ではある分の平均です。CPU対戦はKPM・反応時間・打ち方も一致する条件で比較します。「同じシードだけで比較」を使うと最新記録のシードに絞れます。TOP10は初期状態ではpoint降順です。同点ならKPM、所要時間、実ミス数、新しい日時で並びます。KPM順位では同速時にpointを優先します。pointは従来の履歴表示と同じ計算式で、当時の加重ミス数（なければミス箇所数）から求めます。

「練習の記録」は、文章選択と同じ雰囲気の固定高さカルーセルで「文章別の記録分析」と「全記録」を横スライドで切り替えます。アニメーション設定とOSの動きを減らす設定に従います。文章別の分析を上、選択中の条件に対応する「過去の記録一覧」を下に配置します。繰り返しの文章名の代わりに挑戦日時を先頭列へ置き、point・KPM・5秒移動平均の最高／最低速度・正確率を併記します。行全体をホバー／フォーカスで強調し、クリックまたはEnter／Spaceでその記録の詳細へ移動します。移動はイーズイン・イーズアウト（0.65秒）で、環境設定に従い、手動スクロールで中断できます。「比較する文章・配列・モード」や同じシードの選択は、グラフ・TOP10・過去一覧へ連動します。

TOP10と推移の指標はpoint・KPM・最高速度・最低速度から選べます。最高／最低は5秒移動平均の値を高い順で比較し、最低速度も高いほど上位です。5秒未満や算出できる要約・ログがない記録は速度ランキングから除外します。分析には完了した挑戦回数も表示し、キャンセル・中断・苦手ワード練習を含めません。TOP保存とのID重複は除外します。過去一覧と全記録は各20件ずつページ送りできます。全記録は日時降順で、文章名・日時・操作ボタンを別段に表示します。point・KPMそれぞれの歴代TOP10も重複をまとめて保持します（条件ごとに最大20件）。今後は200件で履歴やログを切り捨てず保持します。以前の制限で削除済みの記録は復元できませんが、TOP記録として残る分は一覧・分析へ統合します。移動平均と前回比較は保存されている全記録から計算します。IndexedDBやlocalStorageが使えない・容量が足りない場合は警告を表示し、開いている画面のメモリに打鍵ログを保持してJSONで書き出せるようにします。再読込前に書き出してください。

### ミス率による接頭辞

50pt刻みの動物名の前に、実ミス率に応じた接頭辞を付けます。例は「星々に祝福されしチーター」「精緻なキツネ」です。実ミス率は **実ミス数 ÷（正しく受け付けた実打鍵数 + 実ミス数）×100**。連続したミスも1回ずつ数え、point用の加重ミス数・ミス箇所数とは分けます。タイプウェルの長い有効な綴りも、ここでは実打鍵数を使います。point計算式・RTCの95%判定は変更しません。

| 実ミス率   | 接頭辞           |
| ---------- | ---------------- |
| 0%         | 星々に祝福されし |
| 0%超〜0.5% | 至高の           |
| 0.5%超〜1% | 研ぎ澄まされた   |
| 1%超〜2%   | 精緻な           |
| 2%超〜3%   | 堅実な           |
| 3%超〜5%   | 歴戦の           |
| 5%超〜8%   | 荒削りな         |
| 8%超〜12%  | 暴走する         |
| 12%超      | 混沌の           |

0%は専用区分で、それ以外は前の上限を超え、表の上限を含みます。0.5%ちょうどは「至高の」、12%ちょうどは「暴走する」です。判定には表示用に丸める前の値を使います。まだ一度も打っていない状態では接頭辞を付けません。動物名はpointで決まり、1000pt以上は従来どおりチーターです。

練習中・CPU対戦・記録一覧・TOP10・詳細・JSON書き出しを同じ称号にそろえます。旧記録も現在の称号で表示しますが、実ミス数が残っていない記録は保存されたミス箇所数を代用し、「旧集約ミス率」と明記します。保存済みの正確率が丸められている場合も、その丸め値からミス率を逆算しません。

## 記録リプレイ

「練習の記録」→各行の「リプレイを見る」、または「詳細を見る」→「リプレイ」で、保存した打鍵ログを再生できます。再生・一時停止・先頭へ・前後1打鍵・0.25/0.5/1/1.5/2/4倍速・時間シークに対応します。同じミリ秒に複数の打鍵があっても、1打鍵送りでは個別に確認できます。

本文・ふりがな・読み・実際に入力したローマ字を表示し、ミスでは入力位置を進めず、入力キーと赤い枠で示します。累計と直近1秒の実打鍵KPM、実ミス数・実ミス率も再現します。倍速は再生時間だけを変え、表示するKPMを倍にしません。タイプウェルは保存時と同じ400/280基準打鍵の終了位置を使います。再生は読み取り専用で、再生操作やキーボード操作から新しい記録を作りません。

時間軸は保存された計測時間です。一時停止・CPUカウントダウン・問題間待機はログに含まれないため再生にも含めません。画面を閉じる、分析タブを切り替える、ブラウザを非表示にすると再生を停止します。ミス率の計算は履歴と同じ実打鍵ベースです。

既存のv1ログも再生し、本文・読みが完全一致する既存データや単語間スペースから表示対応を復元します。対応データがない場合は文章全体を1つの読みの単位として表示しますが、入力キーとローマ字位置はログから再現します。今回以降のログには本文／読みの区切りも保存するため、辞書に依存せずふりがなと位置を再現できます。打鍵ログがない旧記録はリプレイできません。保存された正誤や入力位置を現在の入力エンジンで再現できないログは、理由を表示して再生を中止します。集計値から打鍵を推測して補完しません。

## 保存記録とのゴースト対戦

「練習の記録」→「ゴーストと対戦」、または記録の詳細→「この記録のゴーストと対戦」で開始します。現在の設定より保存記録の入力配列を優先し、保存済みの本文・読み・問題順を直接使用します。シードと出題バージョンも引き継ぐため、辞書の変更やシャッフルによって別の問題へ変わりません。打鍵ログがない記録、現在の入力判定で再現できないログは理由を表示し、集計値から入力を推測しません。

最初の打鍵でプレイヤーとゴーストの時計が同時に始まります。ゴーストは実際の別綴り、ミス、打鍵間隔を保存時刻どおりに再生し、ミスでは進みません。プレイヤーも別の有効なローマ字表記を使用できます。YOU/GHOSTそれぞれの文章・読み・実入力・実ミス数・KPMと、共通の距離で比較する進捗バー・先行状況を表示します。次の文章は表示しません。

勝敗はログの最終到達地点へ先に到達した側で決まり、同時ならDRAWです。距離は自然なローマ字で残り何打か（かなは濁点別打鍵）を基準にし、余分な別綴りで進捗を水増ししません。タイプウェルの400/280打の固定終了位置も維持します。CPU戦や60秒トレーナーで途中終了した文章は、そのとき到達した位置までを目標にします。自然打鍵の進捗がなかった文章はプレイヤーの入力対象から除き、元ログのゴースト表示ではその待ち時間・ミスも再現します。最後の到達後の待機時間は勝敗に含めません。これはRTCのラウンド対戦ではなく、保存ログの到達地点までのタイムレースです。

一時停止ボタン・Escape・入力欄からのフォーカス移動・タブ非表示で両者の時計を止め、再開時に同じ時点から進めます。リプレイと同じく、元ログに保存されていない休止時間・CPU幕間は含みません。「同じゴーストと再挑戦」で入力と時計をリセットできます。

完走した対戦は「ゴースト対戦」として独立して保存し、元記録と元ログを変更しません。新しい記録にも打鍵ログが付くので、詳細分析・リプレイ・さらなるゴースト対戦が可能です。中断・画面移動・再挑戦では途中記録を追加しません。pointには通常と同じ加重ミス式を使い、タイプウェルでは基準打鍵数、それ以外は正しい実打鍵数から算出します。通常練習の自己ベストには混ぜず、記録分析では同じ元記録とのゴースト対戦を1グループとして比較します。

通常練習は開始前に15問、CPU対戦はBO7全体の最大133問分を生成します。同じセット・シード・出題v1なら同じ組み合わせと順序になり、通常練習の15問はCPU対戦の先頭15問とも一致します。同じシードなら配列変更でも問題は同じです。固定シード・全文確認・履歴からのシード再出題に対応します。RTC競技の勝敗ルールはCPU対戦の10点先取・4ラウンド先取・正確率95%判定を使います。ソロの出題数とpoint計算はGALACTYPEのルールです。

RTC公式で公開されたZIPは再配布の許諾を確認できていないためGit管理対象から外し、手元の原本を `data/sources/rtc/` に保存します（`.gitignore` 対象）。必要な5ファイルは [原本の配置手順](data/sources/rtc/README.md) を参照してください。すべてそろえたうえで `python3 scripts/import-rtc.py` を実行すると、アーカイブを展開せず読み、`src/data/generated/rtc.json` を再生成できます。通常のクローン・CI・ビルドにはZIPは不要です。ZIP/XMLのSHA-256、メンバー名、著者、元の本文・読みを保持します。出題v1の辞書・抽出順を変更する場合は新しい出題バージョンとして扱います。

原文の本文表記は保持し、入力用の読みはカタカナをひらがな、大文字英字を小文字、全角英数記号を半角にそろえます。英字の大小は区別しません。かな配列でも英字・記号の区間は対応するJIS英数キーで入力できます。中点はローマ字入力で `/`、かな入力では `Shift + Slash` です。提供データの「また笑えばいい 」には読みのない末尾空白があるため、表示には残し、打鍵は追加しません。曖昧な漢字の読み対応はインポータ内で確認済みの対応を明示しています。

## 保存HTMLから追加した打鍵トレーナー

「打鍵トレーナー · 高速タイピング」（18文）と「打鍵トレーナー · 長文鍛錬用」（15文）を文章ライブラリの「60秒トレーナー」から選べます。Space→3秒カウント後に60秒計測し、収録文からシード付きでランダム出題します。同じ文の連続を避け、シード固定・履歴からの再現・打鍵ログ・リプレイ・ゴーストにも対応します。CPU対戦の文章セットとしても選べます（CPU対戦では既存のRTCラウンドルールを使用）。全文確認は1周目の出題順だけを表示します。

ユーザー提供のCP932保存HTMLから `view_base`（本文）、`input_base`（読み）、`advance_base`（文字と読みの対応）、`playtime=60` を抽出しました。末尾の空文字は終端として除外し、本文・読みは表記や順序を保っています。ふりがなは元の文字対応データから作成し、推測していません。広告・画像・HTML内のゲームスクリプトは取り込み・実行しません。

- 高速タイピング: [タイパー養成所・元ページ](http://typing.tsurizamurai.com/daken_010/type.cgi)
- 長文鍛錬用: [タイパー養成所・元ページ](http://typing.tsurizamurai.com/daken_003/type.cgi)

データのみの抽出元スナップショットを `data/sources/trainers/`、生成データを `src/data/generated/trainers.json` に保存しています。スナップショットには元ファイル名・CP932・保存HTMLのSHA-256・元URLを記録しています。再生成は `python3 scripts/import-trainers.py`。元の保存HTMLから取り直す場合は、同コマンドに2ファイルのパスを渡します。

## 日本国憲法 条文集

## トレーナーの周回と文章ライブラリの分類

トレーナーの新規出題（v2）は、収録された全文を1回ずつ打つと1周とし、2周目以降も周ごとに新しくシャッフルして60秒間出題し続けます。1周目の順番を固定で繰り返す方式ではありません。周の境目で同じ文が連続することも避けます。全文確認には1周目だけを今回の出題順で表示し、シード固定・履歴からの再出題では2周目以降も同じ順序を再現します。過去のv1記録は従来の抽選方式で再現し、新規v2の記録とは分けて保存します。

ライブラリでは、日本国憲法の前文と条文集を「公的文書」、既存の文学・旅・科学・日常・思索・音楽の6文章を「オリジナル」、タイプウェル4種目とタイプウェル準拠の宇宙の名前を「タイプウェル」にまとめます。「オリジナル長文」は「オリジナル」の右隣に表示します。6文章の元のテーマはカード表示と検索で維持し、宇宙の名前のタイトルの「タイプウェル準拠」表記も維持します。

RTC2019とRTC2023は、提供された `RTC2019word5.zip`・`RTC2023word2.zip` 内の全8 XMLから追加しています。本文・読み・パート内の順序・重複を保持し、他年度と同じシード付きのパート連結方式で出題します。先頭の画面画像は、Spaceカウントが終わって実際に入力した後の画面です。

## オリジナル長文

「オリジナル長文」にユーザー提供の21編（7テーマ × 初級・中級・上級）を収録しています。選択・全文確認後、各編の全文を1問として入力します。句点での出題切り替えや次文表示はなく、最後まで打つと1回の練習記録として保存します。入力中の本文は折り返さない一本の行で、現在位置に合わせて横へ送ります。かな・ローマ字のガイド、9配列、一時停止・再開、やり直し、リプレイに対応します。単語の色分けはデフォルトONです。入力済み単語を消す設定でも一本の行を維持します。

原本 `typing_long_passages_21.json` は本文・タイトル・分類・難易度を変更せず `data/sources/original-long/` に保存しています。原本に含まれない読みは `readings.json` の明示的な本文／読み対応として管理し、SHA-256・本文一致・文字数を検査して `src/data/generated/originalLong.json` を生成します。再生成は `python3 scripts/import-original-long.py`、一括照合は `python3 scripts/rebuild-data.py --check`。詳細は [読みデータの管理](data/sources/original-long/README.md) を参照してください。
